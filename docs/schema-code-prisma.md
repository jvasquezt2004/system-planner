# Prisma schema mapping

The Prisma code format targets Prisma ORM 7.10.1. It emits the Prisma 7
`prisma-client` generator and a PostgreSQL datasource without a URL; Prisma 7
reads datasource URLs from `prisma.config.ts`. Designs using pgvector also
enable the `postgresqlExtensions` preview feature and declare the `vector`
extension.

PostgreSQL scalar types use Prisma scalar types with `@db.*` native types when
Prisma supports them. PostgreSQL `cidr`, `macaddr`, `interval`, and pgvector
columns use `Unsupported(...)` because Prisma has no matching native scalar.
Array columns use Prisma list types. Prisma does not permit optional list
fields, so nullable PostgreSQL arrays are emitted as required lists. Their
nullability mismatch is documented once in the grouped migration-note footer.

Prisma `autoincrement()` cannot distinguish PostgreSQL `GENERATED ALWAYS` from
`GENERATED BY DEFAULT` identity. Generated schemas include a migration note for
this difference. PostgreSQL features that Prisma cannot represent—pgvector
indexes, INCLUDE columns, NULLS NOT DISTINCT, and access-method storage
parameters—have concise in-model comments and exact raw SQL statements in the
single grouped migration-note footer. Prisma schema code does not replace
PostgreSQL migrations for those features.

Enums map each database label and type name. Singular model names, field names,
and forward/backward relation fields use the shared schema naming plan;
`@@map` and `@map` preserve database names. Relation labels are stable names
derived from endpoint models and forward fields, not design IDs. Relationships
include PostgreSQL referential actions; explicit junction models retain their
endpoint-pair unique constraint. Prisma cannot expose implicit many-to-many
shortcuts such as `Post.tags` for these junctions without introducing a
different join table, so the generated API uses the explicit junction model's
two relations.
