# Prisma schema mapping

The Prisma code format targets Prisma ORM 7.10.1. It emits the Prisma 7
`prisma-client` generator and a PostgreSQL datasource without a URL; Prisma 7
reads datasource URLs from `prisma.config.ts`. Designs using pgvector also
enable the `postgresqlExtensions` preview feature and declare the `vector`
extension.

PostgreSQL scalar types use Prisma scalar types with `@db.*` native types when
Prisma supports them. PostgreSQL `cidr`, `macaddr`, `interval`, and pgvector
columns use `Unsupported(...)` because Prisma has no matching native scalar.
Array columns use Prisma list types. Prisma does not permit optional list
fields, so a nullable PostgreSQL array is emitted as a required list with an
inline comment documenting the nullability mismatch.

Prisma `autoincrement()` cannot distinguish PostgreSQL `GENERATED ALWAYS` from
`GENERATED BY DEFAULT` identity. Generated schemas include a migration note for
this difference. PostgreSQL features that Prisma cannot represent—pgvector
indexes, INCLUDE columns, NULLS NOT DISTINCT, and access-method storage
parameters—are retained as comments and raw SQL migration statements where
needed. Prisma schema code does not replace PostgreSQL migrations for those
features.

Enums map each database label and type name. Models and fields use valid,
collision-free generated names with `@@map` and `@map` preserving their database
names. Relationships include both Prisma relation fields and PostgreSQL
referential actions; explicit junction models retain their endpoint-pair unique
constraint.
