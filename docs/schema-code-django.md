# Django ORM schema code

The Django generator targets Django 6.1 and PostgreSQL. It emits one `models.py` for an app; generated model metadata preserves the design table and column names, and model fields use valid Python identifiers. Install `pgvector` for vector fields and add `pgvector.django.VectorExtension()` in a migration when a design uses pgvector.

## PostgreSQL-specific mappings

- PostgreSQL enum types become `TextChoices` and `CharField(choices=...)`. Django has no native PostgreSQL enum field; generated comments include `CREATE TYPE` and `ALTER COLUMN ... TYPE` guidance for a `RunSQL` migration.
- Structured literals use Django `db_default`; timestamp and UUID defaults use `Now()` and `gen_random_uuid()` database expressions. Django's `Now()` emits `STATEMENT_TIMESTAMP()`, not transaction-start `CURRENT_TIMESTAMP`.
- `BigAutoField`, `AutoField`, and the small-integer primary-key field use `GENERATED BY DEFAULT AS IDENTITY` on PostgreSQL. The design SQL uses `GENERATED ALWAYS AS IDENTITY`; generated comments call out this difference. Non-primary-key identity columns need a raw SQL migration.
- Django 6.1 database-level `DB_CASCADE`, `DB_SET_NULL`, and `DB_SET_DEFAULT` match those foreign-key actions. `NO ACTION` uses `DO_NOTHING`. Django has no database-level `RESTRICT` option, so generated comments require a raw SQL migration for `ON DELETE RESTRICT`. `ON UPDATE` actions also require raw SQL. Django foreign keys are emitted `DEFERRABLE INITIALLY DEFERRED`, unlike the design SQL's immediate foreign keys; comments call this out.
- Many-to-many associations use an explicit through model and retain the editable junction table and endpoint-pair uniqueness.
- PostgreSQL index methods map to Django/PostgreSQL index classes; HNSW and IVFFlat use pgvector's index classes. PostgreSQL object names longer than Django's 30-character constraint/index-name limit are shortened deterministically with a hash, and a generated comment records the required raw SQL alternative to retain the original name.
- Types Django does not model natively use a small custom `PostgreSQLTypeField`; array columns use `ArrayField`. Unique indexes are represented as `UniqueConstraint`; Django can preserve their uniqueness, keys, supported opclasses, INCLUDE columns, and null semantics, but the resulting PostgreSQL object is a constraint-backed unique index and may not preserve non-default index method or ordering details.

## Validation

The generator snapshots in `src/shared/schema-code/django.test.ts` verify deterministic source output. The ignored `.orm-check/` harness runs Django system checks, creates migrations, renders PostgreSQL `sqlmigrate` output without a live server, and compares the generated schema's tables, columns, defaults, constraints, relationships, and indexes to `generateDesignSql`.
